# 概要设计说明书（todo）

> 由 DesignAgent 基于 requirements.md 生成。

## 1. 架构分层

```text
+-----------------------------+
|        CLI 交互层            |  argparse 解析 add/list/done/delete/stats
+-----------------------------+
|        应用服务层            |  add_task / complete_task / delete_task / stats
+-----------------------------+
|        数据持久层            |  JSON 文件读写，Task <-> dict
+-----------------------------+
|          实体层              |  Task 数据类
+-----------------------------+
```

## 2. 模块划分

| 模块 | 职责 | 对外接口 |
|------|------|----------|
| app.py | 实体、服务与 CLI 入口 | main(argv) -> int |
| test_app.py | 服务层自动化测试 | unittest 用例 |
| tasks.json | 运行期数据文件（自动生成） | JSON 数组 |

## 3. 数据模型

Task 字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 自增唯一编号 |
| title | str | 事项标题，不允许为空 |
| done | bool | 是否完成 |
| created_at | str | 创建时间（YYYY-MM-DD HH:MM:SS） |

## 4. 命令接口

| 命令 | 参数 | 行为 | 退出码 |
|------|------|------|--------|
| add | 标题 | 新增事项并持久化 | 0 / 2（空标题） |
| list | 无 | 打印全部事项与状态 | 0 |
| done | ID | 标记完成 | 0 / 2（ID 不存在） |
| delete | ID | 删除事项 | 0 / 2（ID 不存在） |
| stats | 无 | 输出总数、完成数、完成率 | 0 |

所有命令支持 `--data` 指定数据文件，便于测试隔离。

## 5. 关键流程

1. 加载 JSON；文件不存在或损坏时返回空列表。
2. 执行命令并修改内存中的 Task 列表。
3. 写命令成功后统一保存，保证退出后数据不丢失。
4. 输入非法时打印错误到 stderr，返回退出码 2，不抛未捕获异常。

## 6. 测试策略

- 用例覆盖：新增编号、完成状态、删除、持久化、统计
- 用临时目录隔离数据文件，避免污染开发数据
- 验收命令：`python -m unittest -v test_app`

## 7. 需求追溯

本设计覆盖 requirements.md 中全部 P0/P1 功能需求；每条需求在 requirements.md 中有唯一 FR 编号，
验收标准由 test_app.py 与 CLI 冒烟验证。
